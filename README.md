# Keitaro Wrapper

Веб-панель для создания кампаний в Keitaro и редактирования офферов в потоках. FastAPI обращается к Keitaro Admin API, а SQLAlchemy хранит импортированные потоки, черновики, закреплённые доли и архив привязок в SQLite. Интерфейс написан на HTML, CSS и JavaScript.

## Установка

Нужен Python 3.9 или новее. Команды ниже рассчитаны на macOS и Linux. Выполняйте их в корне проекта, где находятся `dev.py` и `alembic.ini`.

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Если в проекте есть `requirements.txt`, установите зависимости из него:

```bash
python -m pip install -r requirements.txt
```

SQLite поставляется с Python. Docker и Node.js для запуска не нужны.

## Настройка

Если у вас уже есть `.env`, подставьте в него данные своего стенда Keitaro. Если файла ещё нет, скопируйте `.env.example` в `.env` из корня проекта:

```bash
cp .env.example .env
```

Затем откройте `.env` и замените значения из шаблона своими. Можно также создать `.env` вручную и заполнить эти переменные:

```dotenv
KEITARO_BASE_URL=https://tracker.example.com
KEITARO_API_KEY=your_api_key
KEITARO_DOMAIN_ID=12
KEITARO_CAMPAIGN_GROUP_ID=34
KEITARO_TRAFFIC_SOURCE_ID=56
```

В `KEITARO_BASE_URL` укажите адрес трекера . Возьмите API-ключ и ID существующих тестовых записей в Keitaro. Числа в примере условные. Для работы на реальном стенде ключу нужны права на чтение каталога и потоков, создание кампаний и потоков и изменение потоков.

## Миграции и запуск

```bash
python -m alembic upgrade head
python -m alembic current
python -m alembic heads
python dev.py
```

После применения миграций `current` и `heads` должны показать одинаковый ID ревизии. SQLite-файл `keitaro.db` находится в корне проекта. В схеме есть таблицы `streams`, `offers`, `stream_offers` и служебная таблица `alembic_version`.

- [Панель](http://127.0.0.1:8000/)
- [Swagger](http://127.0.0.1:8000/docs)
- [Проверка запуска](http://127.0.0.1:8000/health)
- [Каталог офферов](http://127.0.0.1:8000/offers)

## Как пользоваться

### Создание кампании

1. Нажмите **«Создать кампанию»**.
2. Введите название, двухбуквенный код страны и выберите существующий оффер из результатов поиска.
3. Подтвердите создание. Панель покажет ID кампании и подставит его в поле импорта.
4. Нажмите **«Импортировать потоки»**.

Кампания создаётся с доменом, группой и источником из `.env`. Первый поток перенаправляет посетителей из указанной страны на Google. Второй поток направляет остальных посетителей на выбранный оффер с долей 100%. При совпадении названия с существующей кампанией проверка дубликатов возвращает сообщение с её ID.

### Редактирование потоков

Введите ID кампании и импортируйте потоки из Keitaro. Кнопка **«Открыть сохранённые»** читает ранее импортированные данные из SQLite. Выберите поток с офферами.

| Действие | Результат |
| --- | --- |
| Добавить оффер | Привязка появляется в черновике. Доли пересчитываются. |
| Удалить | Привязка становится неактивной и отображается с долей 0%. |
| Восстановить | Оффер снова участвует в распределении долей. |
| Закрепить | Доля оффера сохраняется при следующих изменениях состава. Остаток распределяется между незакреплёнными офферами. |
| Отменить черновик | Панель возвращается к опубликованному состоянию. |
| Опубликовать в Keitaro | Бэкенд отправляет черновик в Keitaro. Удалённые привязки остаются доступны в локальном архиве. |

Раздел **«Офферы»** показывает доступный каталог Keitaro. Кнопка **«Обновить»** перечитывает его.

## Локальная проверка с пятью офферами

Используйте `mock_keitaro.py` из корня проекта. В его списке `offers` должны быть пять записей с ID от `101` до `105`. Для чистого прогона можно использовать отдельную копию проекта со своим SQLite-файлом. Выполните миграции в этой копии.

В первом терминале активируйте `.venv` и запустите заглушку:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m uvicorn mock_keitaro:app --host 127.0.0.1 --port 8001
```

Оставьте первый терминал открытым. Во втором терминале активируйте то же окружение и запустите панель с тестовыми параметрами:

```bash
KEITARO_BASE_URL=http://127.0.0.1:8001 \
KEITARO_API_KEY=local-test \
KEITARO_DOMAIN_ID=1 \
KEITARO_CAMPAIGN_GROUP_ID=1 \
KEITARO_TRAFFIC_SOURCE_ID=1 \
python dev.py
```

Параметры этой команды действуют для запуска панели. Оба сервера должны работать одновременно. Проверьте, что [каталог заглушки](http://127.0.0.1:8001/admin_api/v1/offers) и [каталог панели](http://127.0.0.1:8000/offers) возвращают пять офферов.

| Шаг | Ожидаемый результат |
| --- | --- |
| Создать `local_test_mx` с кодом `MX` и оффером `101` | Панель выдаёт ID. После импорта видны два потока. В офферном потоке `101` получает 100%. |
| Создать кампанию с тем же названием | Панель показывает сообщение о существующей кампании и её ID. |
| Добавить офферы `102`, `103`, `104`, `105` по одному | В черновике пять офферов по 20%, если доли свободны. В заглушке пока только `101` с долей 100%. |
| Отменить черновик | В панели снова только `101` с долей 100%. |
| Повторно добавить четыре оффера и опубликовать | В панели и заглушке пять офферов по 20%. |
| Закрепить `101` на 20% и удалить другой оффер | Закреплённый оффер сохраняет 20%. Три оставшихся незакреплённых получают 27%, 27% и 26% в некотором порядке. |
| Опубликовать удаление, затем восстановить оффер | После публикации удалённая привязка отсутствует в заглушке и доступна для восстановления в панели. После восстановления и публикации снова пять офферов по 20%. |

Чтобы проверить состояние заглушки, откройте [её Swagger](http://127.0.0.1:8001/docs) и вызовите `GET /admin_api/v1/streams/{stream_id}` с ID второго потока. Сравните ответ до и после публикации. Заглушка хранит кампании и потоки в памяти. После её перезапуска создайте тестовую кампанию заново.

Этот сценарий проверяет интерфейс, собственный API, хранение черновика и отправку изменений. На реальном стенде отдельно проверьте права ключа, создание и публикацию кампании и фактическую маршрутизацию трафика.

## Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| `502` в локальном режиме | Заглушка запущена на порту 8001. Каталог доступен по прямому адресу. Панель запущена с тестовым `KEITARO_BASE_URL`. |
| Keitaro отвечает `401` | Адрес стенда, API-ключ и права на конкретную операцию. |
| Ошибка при создании после получения ID или alias | Найдите кампанию по ID или alias и проверьте, какие потоки успели создаться. |
| SQLite сообщает об отсутствующей таблице | Выполните `python -m alembic upgrade head` из корня проекта. |
| Оффер отсутствует в списке добавления | Обновите каталог и проверьте, доступен ли оффер ключу и не привязан ли он уже к потоку. |
